🔧 CONFIGURATION GUIDE: WHERE TO SET THE URL
═══════════════════════════════════════════════════════════════════════════

The app is configured via environment variables in these priority order:

1. HIGHEST: Runtime environment variables
   $ export MEMBERS_WEB_API_BASE=/api
   $ python3 run.py

2. MEDIUM: .env file (den_server/.env)
   MEMBERS_WEB_API_BASE=/api
   
3. LOWEST: Defaults (in app/config.py)
   API_BASE defaults to: /api
   TIMEZONE defaults to: Asia/Kolkata

APP ROUTES:
  /members                 ← Main app (Jinja2 rendered)
  /members/app.js          ← App logic
  /members/manifest.json   ← PWA manifest

TO CHANGE PORT:
  $ PORT=3000 python3 run.py
  → App will be at http://localhost:3000/members

TO CHANGE THE /members PATH:
  Edit den_server/app/routers/members_web.py
  Change: router = APIRouter(prefix="/members", ...)
  To:     router = APIRouter(prefix="/app/members", ...)
  
  Then access at: http://localhost:8000/app/members

💡 HOW IT WORKS (Technical Overview)
═══════════════════════════════════════════════════════════════════════════

OLD ARCHITECTURE:
  Client → den_mem_web (Python) → den_server (FastAPI)
  2 processes, CORS needed

NEW ARCHITECTURE:
  Client → den_server (FastAPI) with Jinja2
     ├── /members → Renders base.html with config
     ├── /members/app.js → Serves app.js
     └── /api/* → All existing backend endpoints

CONFIG INJECTION:
  1. User requests: GET /members
  2. FastAPI handler renders: Jinja2("base.html", config={...})
  3. HTML includes: <script>window.DEN_CONFIG = {...}</script>
  4. Client JS reads: window.DEN_CONFIG
  5. API calls use: window.DEN_CONFIG.API_BASE (usually /api)

SAME-ORIGIN: No CORS needed because frontend and backend are same server!
